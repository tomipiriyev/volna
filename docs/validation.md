# Validation

The physics is validated independently of how results look. There are three
layers.

## 1. Unit and analytical tests (`ctest`, `cpp/tests`)

| Test | What it proves |
|---|---|
| TM110 cavity resonance vs the discrete Yee dispersion relation (< 1e-4) | Update equations, rectilinear spacings |
| ∇·H preserved to float32 round-off on a graded grid | Discrete curl consistency |
| Gaussian pulse: analytic spectrum vs sampled DFT (< 1e-6); DC-free | Excitation and DFT |
| PEC sheet and wire rasterization edge counts | CAD-to-grid rule for degenerate boxes |
| Port errors: edge inside conductor, off-grid port | No silent shorts |
| TEM parallel-plate line with PMC walls, CPML ends and a sheet port: \|Z_in\| = η₀h/(2W) within 2% (measured 0.01%); Re Z_in > 0; P_acc = P_inc(1 − \|S11\|²) | Port voltage, current and sign; CPML at normal incidence; PMC |
| Short dipole: D = 1.5 within 0.05 dB (measured 1.783 vs 1.761 dBi for 0.11λ); sin²θ RMS < 1% (measured 0.37%); P_rad(far field) = P_rad(Poynting) = P_acc within 1–2% | NF2FF transform, quadrature, energy balance |
| Single-thread vs multi-thread bitwise identical with port, CPML and NF2FF | Deterministic parallelism |
| Voxelizer: ray caster counts shared edges once and handles inside-out meshes | Watertight inside/outside test |
| Voxelizer: a grid-aligned box mesh gives exactly the edges of the box primitive; an offset box follows the 50% coverage rule | PEC rule for triangle meshes |
| Voxelizer: tessellated sphere dielectric volume error falls with the grid (0.47% at 16³, 0.003% at 32³) | Cell-centre dielectric sampling |
| Voxelizer: a rectangular sheet mesh equals the zero-thickness box; a disc footprint stays inside its circle | Sheet footprint rule |
| Voxelizer: equal-priority dielectric overlap is an error, priorities resolve it; DC path, loop and floating port detected | Overlap and feed checks |

### STEP path (M3)

The patch case is written by `node validation/cases/make_step_cases.mjs`,
which runs the app's own TypeScript (STEP import, classification, mesher,
problem builder) under Vite's SSR loader. It writes two problems on the
same grid:

- `patch_step` uses triangle-mesh and sheet objects from the simulation
  tessellation.
- `patch_step_prim` replaces each CAD object with its bounding box.

For box-shaped CAD the two must give identical fields, so comparing them
isolates the CAD path (tessellation, voxelizer, sheet footprint). openEMS,
which has no mesh objects, runs the primitive twin. Measured on
2026-10-25:

- The STEP-built and primitive problems are bitwise identical.
- Against openEMS, f_res is 2.3401 GHz in both, Z_in differs by at most
  0.18%, D by 0.009 dB and efficiency by 0.002.

`app/tests/pipeline.test.ts` repeats the identity check on every unit-test
run:

- The square-arm dipole STEP fixture against the M2 programmatic case
  `dipole_sq_h2.5`, on its grid.
- The patch against its primitive twin, on a short capped run.

It also runs the cylindrical-wire dipole fixture end to end.

### Why the numbers differ from textbook values

The 2.15 dBi and 73 + j42.5 Ω of a half-wave dipole assume an infinitely
thin wire with a sinusoidal current, fed across an infinitesimal gap. The
numerical model differs in four ways:

- **Wire radius.** A single line of PEC edges has an effective radius of a
  fraction of a cell. This model's L/a ≈ 400, which moves the series
  resonance below L = λ/2. It happens at L = 0.465λ, where R = 72 Ω and
  X = 0.
- **Feed gap.** The gap is one cell (2.5 mm), and its capacitance is part of
  Z_in.
- **Discretisation.** Grid dispersion and staircasing.
- **Boundaries.** PML reflection and DFT truncation, both quantified above.

Directivity barely depends on these effects, so it is checked tightly
against theory. Impedance is checked against the physical range and tightly
against openEMS on the same grid.

Wire models are not used for mesh refinement. Refining a 1D wire also
shrinks its effective radius, so the physical problem changes with every
level. The refinement study uses solid arms with a fixed cross-section
instead.

The monopole's ground is finite (1λ square), so the infinite-ground values
(5.15 dBi, about 36.5 Ω) are limits, not targets. A finite ground tilts the
beam; here it peaks at θ ≈ 44°, with D = 3.6 dBi.

## 3. Browser end-to-end (`npx playwright test`)

- The validation dipole runs in the production build in headless Chromium,
  once with the multi-thread build (cross-origin isolated) and once with the
  single-thread build (headers off). Its series resonance must match the
  native solver.
- A running solve can be cancelled.
- The model and project tests from M1a.
- M5 (`m5-webgpu.spec.ts`, Chromium new headless with the real GPU):
  - Fields after 1000 steps match the C++ solver within 1e-4 relative L2,
    for the dipole and the STEP patch. Measured: about 1e-6.
  - Complete runs agree within 0.5% on Z_in and 0.02 dB on D, with
    identical step counts. Measured: ≤ 1e-6 and < 1e-4 dB.
  - A WebGPU run through the app works, and so does the device-lost
    fallback to the CPU.
- M4: the patch run opens on the Results step, which checks:
  - the S11, VSWR and Z_in plots and both polar cuts with HPBW;
  - the peak quantities;
  - quantity and polarization switches;
  - the port CSV, which must be byte-identical before and after changing
    the display range and scale;
  - pattern CSV, SVG and PNG exports;
  - a project saved with results and reopened, whose result becomes
    current after Validate.
- M3: the patch fixture goes through Import → Assign → Feed → Frequency →
  Mesh (390,400 cells, as in `patch_step`) → Validate. Validate must report
  the same PEC edge and dielectric cell counts as the native run. The patch
  is then simulated with a loose end criterion; results appear and become
  stale after an input change. A second test cancels a running
  simulation.

## Reproducing

```bash
cd cpp && cmake --preset native-release && cmake --build --preset native-release && ctest --preset native-release
cd .. && python3 validation/cases/make_cases.py
source ~/opt/openEMS/venv/bin/activate && python validation/openems/run_problem.py validation/cases/dipole/problem.json
node validation/cases/make_step_cases.mjs
python validation/openems/run_problem.py validation/cases/patch_step_prim/problem.json
node validation/run_validation.mjs --rerun --wasm
```
